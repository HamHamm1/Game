# M2.4 — Art / Beauty Pass — Design & Implementation Reference

> **Canonical implementation reference for M2.4.** Approved 2026-09-05.
> Turns the grey-box village into a place worth stopping to look at,
> Android-first, preserving all M2.1–M2.3 behavior. Shipped as small,
> individually-validated + device-tested sub-milestones A→G.

## 0. North star & non-negotiables
- **Target:** *"สวยมาก เหมือนหลุดเข้าไปอยู่ในชนบทญี่ปุ่น"* — the player stops,
  looks around, and walks on because the place is beautiful and alive.
- **Not "add more assets."** Beauty from composition + M2.2 lighting +
  material cohesion + hero concentration + vegetation life.
- **"AAA-looking ≠ AAA cost."** Max atmosphere per GPU-ms: selective geometry,
  instancing, LOD, texture discipline, simple mobile materials, hero-detail
  concentration. Reference the *feeling* of Genshin Impact — **nothing
  copied**; all original/procedural.
- **Preserve M2.1–M2.3 exactly:** navigable layout, PlayerSpawn,
  LocationEntryPoint/ExitPoint contracts, interiors, pickups, the door, and
  M2.2 lighting + M2.3 weather ownership (the lighting controller stays the
  sole environment writer; art writes no environment/lights).

## 0.1 Locked decisions (owner)
- **Hero buildings (3):** Bathhouse, Player Home, Restaurant.
- **Hero window/lantern glow:** APPROVED, **material/emissive only, NO dynamic
  lights**, and **not a substitute for actual lighting**. Practical/dynamic
  lighting remains deferred to **M2.6**.
- **Sequence:** A first → implement → validate → cloud APK → Android device
  test → **stop for acceptance before B**. No sub-milestone starts until the
  previous is accepted on device.

## 0.2 Ownership map
| Layer | may | may NOT |
|---|---|---|
| Materials/meshes/vegetation/dressing/hero scenes | create/replace geometry & materials; read GraphicsManager intents | write Environment/DirectionalLight3D/fog_density, add dynamic lights, change save format, touch weather/lighting controllers |
| Region/interior scenes | re-dress, add detail, swap hero placeholders | change spawn, entry/exit contracts, scene-load API |
| GraphicsManager | read intents; optionally add read-only intents | change existing preset keys' meaning |

## 0.3 Deferred across all of M2.4 (owner-locked)
Dynamic lanterns/street/window/practical **lights** (→ M2.6), wet-material
response, detailed vegetation-wind sway, advanced weather/audio,
NPCs/cooking/dialogue, interior hero-dressing.

## M2.4-A — Materials (shared library) — TEXTURE-FREE
**Goal:** replace per-primitive flat colors with a small, cohesive, texture-free
**shared material library** whose tuned StandardMaterial3D properties (albedo,
roughness, metallic where appropriate) + M2.2 lighting substantially improve
the greybox. Prove this before any textures.
- **New:** `godot/src/world/material_library.gd` (`MaterialLibrary`): a static
  cache of named, shared, tuned `StandardMaterial3D`s (ground, grass, path,
  water, wall tones, roof tones, structural wood, foliage, interiors, metal)
  plus `tuned_color(color)` — a cached, tuned material for arbitrary-color
  props so every existing color-based primitive is shared + tuned with no
  call-site change. **No textures.**
- **Affected:** `blockout_util.gd` (color helpers route through
  `MaterialLibrary.tuned_color`; add `static_box_mat`/`visual_box_mat` taking a
  material key; `add_tree` uses named foliage/wood); `blockout_town.gd` (major
  surfaces — ground, street, house walls/roofs, bathhouse, pond, river, park —
  switched to named keys for per-surface tuning; small props ride the tuned
  color path). Interiors improve automatically via the tuned color path
  (named interior materials are a later interior pass).
- **Ownership:** MaterialLibrary owns look data only; no environment writes.
- **Perf:** *positive* — shared materials replace dozens of one-offs (fewer
  state changes, better batching); texture-free keeps APK small; roughness
  tuning lets M2.2 light read surfaces as material, not flat paint.
- **Deferred:** all textures/normal/AO maps, animated water, emissive (→ D),
  named interior materials, metallic surfaces beyond a library entry.
- **Android test:** village reads as cohesive tuned wood/stone/plaster/water at
  all 4 times of day and in rain/mist; water catches the sun; LOW FPS
  unaffected; no z-fighting; small APK delta.

## M2.4-B — Vegetation (instanced) — *not started*
MultiMesh grass/ferns/shrubs/flowers/rocks + LOD trees; density gated by
`GraphicsManager.vegetation`. New `vegetation_field.gd`, `vegetation_kit.gd`,
LOD tree. Deferred: wind sway. (Full detail in the approved plan.)

## M2.4-C — Terrain / Nature dressing — *not started*
Gentle low-poly sculpted hero-area ground (flat plane retained for
walkability), stone paths, bridges, fences, drainage, rocks, moss, better
water. New `nature_kit.gd`, optional `ground_hero.tscn`. Deferred: heightmap
terrain/streaming.

## M2.4-D — Hero Buildings (Bathhouse, Player Home, Restaurant) — *not started*
Dedicated hero `.tscn`s with deep eaves, exposed posts/beams, sliding doors,
engawa/veranda, stone foundation; hero-tier (few small textures) materials;
framing vegetation; **material-only emissive** window/lantern glow (no dynamic
lights); small "someone lives here" props. Swap code placeholders for hero
scenes at the same transforms, preserving LocationEntryPoint. Deferred: hero
interiors, dynamic lights (M2.6).

## M2.4-E — Composition / Landmarks — *not started*
Sightlines/framing, distant low-poly hills/mountains backdrop, secondary
landmarks, per-building variation (no two identical), old+modern mix (utility
poles/wires/bicycle/signage — modest). New `distant_backdrop.tscn`,
`landmark_kit`.

## M2.4-F — Android Performance / LOD — *not started*
`lod_util.gd` (visibility_range/impostor/per-preset density), optional
read-only `hero_detail` intent; instancing, culling, batching, atlasing,
draw-call budget; reflections only HIGH/ULTRA. LOW must stay stable.

## M2.4-G — Validation & Android acceptance — *per sub-milestone*
Headless (material sharing/identity, later vegetation determinism + LOD +
hero entry-point preservation + ownership guard), static+boot, and on-device
acceptance (the stop-and-look test, FPS per preset, LOW stability).

## Cross-cutting
All original/procedural; textures (later tiers) small and hero-concentrated;
each sub-milestone additive & reversible; docs (ART_DIRECTION,
MOBILE_ART_DIRECTION, MASTER_SESSION_HANDOFF, CHANGELOG) updated as-built.
