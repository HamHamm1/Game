# M2.3 — Weather Foundation — Design & Implementation Reference

> **Canonical implementation reference for M2.3.** Approved 2026-09-05.
> Scope: a peaceful, Android-first weather foundation. Keeps the M2.2
> lighting look identical when weather is Clear. **Not M2.4.** No lanterns/
> street/window/practical lights, no wet-material response, no detailed
> vegetation-wind response, no advanced weather/audio — all deferred.

---

## 0. Scope & creative guardrails

- **States (M2.3 subset):** `CLEAR`, `OVERCAST`, `LIGHT_RAIN`, `MIST`
  (localized), plus a cross-cutting **`wind`** scalar (0..1).
- **Reconciliation with GAME_SYSTEMS §2** (canonical: clear/cloudy/rain/
  heavy rain/fog/storm): M2.3 ships the peaceful foundation —
  `OVERCAST`≈cloudy, `LIGHT_RAIN`≈gentle rain, `MIST`≈*localized* fog.
  **Heavy rain / storm / lightning / global fog are deferred** (stormy /
  horror-adjacent). Wind is a scalar, not a state.
- **Peaceful, non-horror, mobile-first:** no heavy global fog, no screen
  tints/filters, no darkening below the M2.2 readability floors, no storm.
  Overcast = naturally diffused cloudy daylight (not a grey overlay); rain =
  cozy melancholy; mist = dreamy, localized. Atmosphere per GPU-millisecond.
- **M2.2 lighting unchanged** except one approved hook (§3). Clear = identity.

---

## 1. Ownership (clean separation)

| Concern | Owner | Notes |
|---|---|---|
| Weather **state**, wind, transitions, RNG, persistence | **`WeatherManager`** (autoload) | Publishes DATA only; **never writes Environment / DirectionalLight3D / fog_density / any GraphicsManager-owned property.** |
| Weather **FX** (rain particles, localized mist, wet-intent) | **`WeatherFX`** (world_root child) | Exterior-only; preset-gated; **no lights, no per-object rain.** |
| **Lighting** (sun/ambient/bg/fog-tint) | **`RegionLightingController`** (M2.2) | Consumes a weather light-modifier as data; still the single env writer for mood. |
| **Fog policy** (enabled, base density, LOW cap) | **`GraphicsManager`** | **Unchanged.** Weather never touches global fog — that is why MIST is localized. |

Discipline: **weather publishes data; the lighting owner consumes it.**
Enforced by an automated ownership test (§10).

---

## 2. Architecture

- **`WeatherManager`** (new autoload, after `TimeManager`): a simple
  deterministic state machine.
  - `WeatherTypes.State { CLEAR, OVERCAST, LIGHT_RAIN, MIST }`; `wind: float`.
  - **Boot = CLEAR** (preserves the M2.2 look), then schedules at most one
    optional deterministic intra-day transition.
  - **Rolls on `WorldEvents.day_started`** via a seeded RNG
    (`seed = base_seed ^ (day * prime)`) against a Clear-dominant weighted
    table; may schedule **one** optional intra-day change at a deterministic
    later minute. No forecasting/scheduling system beyond this.
  - Emits `WorldEvents.weather_changed(old, new)`.
  - Data API (no side effects): `current_state()`, `current_wind()`,
    `light_mod() -> WeatherTypes.LightMod`, `fx_spec() -> WeatherTypes.FxSpec`.
  - Persistence: `{ state, wind, base_seed, pending_at, pending_state }`.
- **`weather_types.gd`** (new, typed `WeatherTypes`): the `State` enum, a
  `LightMod` value object (desaturation / darken / tint+strength / fog-tint+
  strength), an `FxSpec` value object (rain / mist / wetness), per-state
  tables, `blend_mod()`, and the weighted `roll()`.
- **`WeatherFX`** (new, world_root child): one camera/player-following rain
  emitter (CPUParticles3D) + a few localized mist planes. Gated by the
  GraphicsManager `effects` intent and by interior context.

---

## 3. The one approved M2.2 hook

1. `WorldEvents` gains one signal: `weather_changed(old:int, new:int)`.
2. `lighting_profile.gd` gains a pure static **`apply_weather(profile, mod,
   blend)`** — subtle desaturate + slight darken + small cool tint + fog-tint
   bias. **CLEAR (all-zero mod) ⇒ identity.**
3. `region_lighting_controller.gd`: subscribes to `weather_changed`, folds
   weather into the resolve chain **base → category → weather → mystery →
   clamp**, and crossfades between weather looks over a bounded tween. It
   writes the *same* mood props as M2.2 — no keyframes, floors, category
   logic, or ownership changed. The readability clamp stays last, so weather
   can never breach the night/interior floors.

`resolve()` gains optional `weather_mod=null, weather_blend=0.0` params;
omitted ⇒ identical to M2.2 (existing tests unaffected).

## 4. Data flow

```
TimeManager.day_started ─► WeatherManager.roll() [seeded] ─► set state (+maybe pending)
        ├─ WorldEvents.weather_changed(old,new)
        │     ├─► RegionLightingController: re-resolve (fold weather mod), crossfade
        │     └─► WeatherFX: fade rain/mist to match (preset + interior gated)
        └─ exposes current_state(), current_wind(), light_mod(), fx_spec()
TimeManager.minute_passed ─► WeatherManager: fire optional pending intra-day change
                          ─► RegionLightingController.apply (folds current weather mod)
location_entered/exited ─► WeatherFX enable/disable exterior FX (interiors unaffected)
game_loaded ─► WeatherManager state restored; controller + WeatherFX resync from it
```

## 5. Performance budget (Android-first)

- State/modifier: a few floats, event-driven (day boundary + one optional
  intra-day change). Lighting fold piggybacks the existing ~1 Hz apply — no
  new steady-state loop. Crossfade is a bounded one-shot tween.
- **Rain:** one player-parented CPUParticles3D (single draw); amount capped
  per preset via `effects` intent; **LOW → OFF** (rain conveyed by lighting
  mod + wind/audio-intent). No per-object rain, no lights.
- **Mist:** a few localized translucent planes; **LOW → OFF**; never global
  volumetric fog.
- **Wind:** one scalar for future vegetation/cloth + audio; ~free now.
- **Wet surfaces:** intent value only in M2.3; material response is M2.4.

---

## 6. Android constraints & LOW safety

- All FX scale off GraphicsManager presets; **LOW spawns no particles/mist
  and no lights** — still readable and stable, weather felt via lighting mod.
- CPUParticles3D (portable) rather than GPUParticles3D.
- Global fog stays exactly as GraphicsManager sets it (LOW cap respected).
- Deterministic and offline; no continuous expensive simulation.

---

## 7. Visual rules (peaceful rural Japan — not a filter)

- **Overcast:** naturally diffused cloudy daylight — small desaturation +
  slight flatten + a touch more ambient. Not a grey overlay.
- **Light Rain:** gentle desaturation + slight darken (clamped) + cool tint +
  rain particles + wet-intent — cozy melancholy, not a storm.
- **Mist:** localized soft haze near water/park + subtle local cool tint;
  global scene stays readable — dreamy, favored at Morning/Night.
- **Wind:** subtle; audio + future sway; no visual filter.
- **Never:** global heavy fog, screen tint/filters, red light, storm, or
  darkening past the M2.2 floors. Mystery stays separate & independent.

---

## 8. Save / load

- New savable `"weather"` → `{ state, wind, base_seed, pending_at,
  pending_state }` via the existing SaveManager registry.
- **Backward compatible:** old saves lacking the key → default `CLEAR`
  (SaveManager only loads keys present in the file). No schema bump.

## 10. Test plan

**Headless (automated):**
- Deterministic rolls (same seed+day ⇒ identical; Clear-dominant); state
  name round-trip.
- Save/load: state+wind+pending restored; old save w/o key ⇒ CLEAR.
- Light-mod: **CLEAR ⇒ resolved profile identical** to no-weather;
  OVERCAST/LIGHT_RAIN desaturate but **stay ≥ readability floors**; MIST
  applies tint yet preserves floors; `blend_mod` interpolates.
- Ownership: WeatherManager exposes data only; controller still leaves every
  GraphicsManager-owned prop (incl. `fog_density`) untouched.
- FX gating logic: target rain/mist = 0 in interior context and at LOW.

**On-device (developer — the real gate):** each state peaceful & readable
across Morning/Day/Evening/Night; rain cozy not stormy; mist localized &
dreamy; overcast soft; night navigable in every state; LOW stable (rain-off
graceful); interiors unaffected; save-in-rain → load-in-rain; smooth
transitions; reads as natural weather, not a filter.

---

## 11. Risks & fallback

- Particle cost on low-end → preset caps + LOW rain-off.
- Mist overdraw/popping → few, soft, distance-faded; LOW disables.
- Ownership creep → test-enforced (weather writes no env props).
- Non-horror discipline → no storm/lightning; floors clamp darkness.
- Additive & reversible — disable WeatherManager ⇒ Clear ⇒ M2.2 look exactly.
